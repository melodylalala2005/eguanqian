# 02 · 市场痛点与需求分析

## 市场痛点与竞品对比

| 痛点 | 具体体现 | 竞品 |
| --- | --- | --- |
| **自动记账识别智能度低** | 自动识别功能无学习优化能力（手动改过后同场景仍错误）；无法解析「和五个朋友垫付 500」这类复杂场景，会直接记为支出 500，不符合实际 | 咔皮记账 |
| **记账体验繁琐无陪伴** | 仅支持手动录入；没有任何激励和互动；不提供情绪价值，用户难以坚持 | 钱迹 |
| **记账分类粗糙，统计失真** | 仅开放一级消费分类，无「餐饮-外卖/聚餐」等二级细分能力；用户需手动选择所有「餐饮」记录才能统计餐饮支出 | 鲨鱼记账 |
| **预算管理粗糙，只有总目标** | 仅支持月度总支出预算，无分类预算；无法单独设置「娱乐」类别上限，也收不到对应超支预警 | 口袋记账 |
| **无法及时有效提醒并给出针对性建议** | 预算提醒多为「月底汇总式」，过程中无实时预警；建议完全模板化，不结合用户消费偏好 | 叨叨记账 |
| **无法持续学习用户习惯给出个性化建议** | 从不分析用户是高频咖啡消费还是偶发大额支出，无法给出「减少每周一杯咖啡支出」这类针对性建议 | 一木记账 |
| **记账与理财数据割裂** | 记账模块与理财模块无数据互通，分析「收支对理财的影响」需手动录入，繁琐且易出错 | 挖财 |
| **财务分析浅层化** | 仅提供收支占比饼图等基础图表，无负债率/偿债能力等健康指标，记多年账仍无法判断自身财务状况 | timi 记账 |
| **负债与投资数据割裂** | 无法自动计算房贷/车贷利息、跟踪还款计划，也不能联动投资数据 | 微信理财通 |

## 需求分析及产品价值

| 痛点 | 需求 | 功能 | 价值 |
| --- | --- | --- | --- |
| 记账体验繁琐 | 记账尽量无感 | OCR＋LLM 低成本无感记账 | 使用意愿强、成本低、容易坚持 |
| 没有情感支持 | 提供情感支持 | ＋角色情感化 AI 记账搭子互动 | 财务健康管理意识增强 |
| 难以长期坚持 | 给予长期激励 | ＋定制化财务健康管理全链条 | 萌生投资意愿 |
| 自动记账识别智能度低 | 自动识别足够智能 | AI 精准识别各种复杂场景并进行智能数据解析 | 轻松应对各种场景 |
| 无法处理日常复杂场景 | 能处理复杂日常场景 | 且能持续学习用户个性化需求 | 可学习用户习惯和未知场景 |
| 分类粗糙，统计失真 | 分类要细致、统计要精准 | 记账数额精准符合财务逻辑；精细分类支持细致统计分析 | 可对消费状况做精细化评估 |
| 预算管理单一 | 预算管理要多样化 | 预算可分类设置；实时跟进细分类别消费状况 | 精准控制特殊类别支出，提前规避超支风险 |
| 无法及时有效提醒 | 需要及时且有效的提醒 | 分类预算实时智能预警；临近超支智能预警 | 方法科学+情感支持+持续激励 |
| 无法给出针对性建议 | 获得针对性建议、可落地方案 | AI 记账搭子情感化引导（及时给出实用建议和细心陪伴） | 财务管理可持续，有助于攒钱计划 |
| 无法持续学习用户习惯 | 系统能持续学习习惯 | AI 持续学习用户消费习惯，在消费前给出个性化建议 | 财务管理贯穿消费前中后，动态调整 |
| 记账与理财数据割裂 | 记账与理财一体化 | 全维度财务健康指标分析（日常消费＋投资＋资产负债） | 清晰掌握财务健康，数据转化为可落地方案 |
| 用户财务信息割裂 | 资产和负债统筹分析 | 自动生成资产负债表；自动计算长期负债利息 | 无多余核算成本，降低财务风险 |
